Open reviews over the working copy two agents

The reviews come first because they are the part that can be acted on. The working copy is below them and is live rather than frozen, because showing the present is its whole job.

  • A changed file already claimed by a review is marked and carries no counts. Its numbers belong to the round that captured it, and the disk has moved on since. Showing a live count next to a frozen review invites a comparison that means nothing.
  • The unclaimed files are the interesting ones. They are work no agent has submitted, which is the thing this view exists to surface. They keep their counts, because the disk is the only thing they are measured against.
  • Nothing here is reviewable. A verdict belongs to a review, and a review is a question an agent asked. Commenting from this view would answer a question nobody put.

A clean tree, and a project git cannot see two states

A project whose work is all committed says so rather than showing an empty panel. A directory that is not a git repository is a project eyeball can still run reviews for, and this one view is what it loses.

  • The warning names what is lost, not what is missing. "No git repository" alone reads as a failure. What matters to the reviewer is that a first round will show whole files rather than a change.
