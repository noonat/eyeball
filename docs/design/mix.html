The reading desk

The direction spec 013 chose on the phone, for a later spec to apply to app.css. Identity from reading and marking up text: Atkinson Hyperlegible for the chrome, code and addresses, one highlighter yellow as the only color that asks for attention, and an eye in the top bar that shows whether anything waits. What this sheet is read first

  • Some of the change is not about type or color. Sentence-case section heads, no middle dots, no monospace outside code and addresses, no dot in a pill, and only waiting rows drawn as cards come from directions.css. The highlighter and the eye are desk.css, and the letter is letter.css, which names no color and takes the desk's.
  • Two typefaces, each in one role. Atkinson Hyperlegible Next and its Mono for the chrome, code and addresses, 109 KB for four files. Literata for what an agent wrote and for a rendered document, 106 KB for two. Each is a variable Latin subset from Fontsource 5.3.0, loaded from fonts/, so a first load shows the fallback until they arrive. All of them loaded in iOS Safari.
  • Every text tone holds 4.5 to 1 on the grounds it sits on, in both themes. One fix was needed and is not about this direction: white Approve text on app.css's green is 3.53, on the current design too, so the green here is darker.
  • Atkinson draws its zero with a slash. It keeps 0 apart from O in an agent name or a path, and it shows wherever Atkinson sets a figure.

The queue three waiting, two working, two settled

The same seven rows queue.html draws. Waiting work is the only card on the screen.

  • The highlighter is the only hue asking for attention. It marks the titles of waiting rows and nothing else on this screen. Working and settled rows are ink, because neither needs the reviewer.
  • A waiting row says what the agent wants. The first line of its note sits under the highlighted title, in the letter's face. The queue does not carry a note today, so serving it is part of applying this.
  • The eye replaces the waiting pill. Its iris is the count. It is in the top bar of every screen, so a reviewer arriving from a notification sees whether answering this review empties the queue.

Nothing waiting the state the reviewer works toward

The empty queue, with the projects eyeball knows about.

  • The eye is shut. Nothing in the top bar asks for anything, and the large shut eye says the same thing at the size of a reward rather than of an error.

A second round document, small change

The second round of a document, as review.html draws it.

  • The letter comes before the title. On a second round it says what was done about the first, which is the question the reviewer opens with. The waiting highlight is on the brief below it.
  • The document is set in Literata, the same face as the letter, because a rendered document is reading too. Code inside it stays monospace.
  • Links are ink. The project name is underlined, the back link is ink. Blue was the accent of the current design and carried no meaning of its own.

A large change a line selected, the composer open

Code, with line 42 chosen for a comment and a comment already on line 45.

  • A line chosen for a comment is highlighted rather than outlined. It is a lighter fill than the marker on a title, so the code on it reads, and it is the same gesture as marking a line on paper.
  • Code keeps its roles. Keywords are a slate blue, because ink keywords would leave four of five syntax roles looking alike. Inside code, color is about the code.
