Queue

The home screen, which answers one question: what needs attention. Waiting is the top of the screen and nothing competes with it. Shown populated across three projects, empty, uninstalled, and with the awkward content that a real week produces.

Foundations Queue Review Widening Project Readme

Populated three projects, four agents

Project and agent are on every row rather than behind a filter, because several of each feed one surface. A filter exists. Needing it in order to see what is waiting would be the failure.

  • The waiting count is in the top bar as well as on the icon badge. Arriving from a notification, the reviewer is on a review page, and this is what tells them whether answering it empties the queue.
  • Working rows carry no size. Nothing has been captured yet, so lines added and removed would be a number about the working copy rather than about anything a person will read.
  • Settled shows the age, not the size. Finding a verdict given an hour ago is the only reason to look, and the size answered a question that is now closed.

Empty, and uninstalled two first states

An empty queue says so plainly and names the projects eyeball knows about, which is also how a project with a misconfigured root gets noticed. An uninstalled surface leads with the two setup steps, because until they are done no notification arrives and an empty queue means nothing.

  • The setup notice sits above the queue rather than replacing it. The surface works without notifications, so blocking the reviews behind a setup screen would withhold what already works to sell what does not.

Awkward content the week that breaks it

Long titles that wrap to three lines, a path-shaped agent name, a review waiting since Tuesday, an eleven-file change, and eight waiting at once. Fixture content is real on purpose: lorem ipsum hides exactly the problems these pages exist to find.

  • A long agent name truncates, a long title wraps. The title is what the reviewer is choosing between, so it gets all the lines it needs. The agent name is an address, and its tail is the part that repeats.
  • Age is coarse and stays coarse. Minutes, hours, days, then a weekday. The number a reviewer acts on is the order, and to-the-minute precision on a four-day-old review is false detail.
  • Nothing sorts by project. Waiting longest is first. Grouping by project would put a fresh request above one that has been waiting since Tuesday, which is the opposite of what the screen is for.
